## 1. 项目内容

### 1.1 一句话主张

> 当模型只有 3M 参数、根本"不会写诗"时，用**解码期的结构化约束**把它变成一个"能写出严格合律近体诗"的系统，并量化**约束强度**与**生成质量**之间的权衡。

### 1.2 这不是"又一个 AI 写诗"

| 常见做法 | 本项目 |
|---|---|
| 模型越大越好，靠数据堆 | 模型固定 ~3M，**不靠加参数**，改进全在解码期 |
| 输出"像诗"即可 | 输出必须通过**程序判定**：平仄、押韵、句式 |
| 只有一个 demo | 六组对照实验 + 人工盲评 + 效率对比 |
| 无法回答"为什么好" | 能回答"约束补上了模型的哪部分能力缺陷" |

答辩时的核心论点：**我们研究的不是"生成诗"，而是"小模型 + 强先验"这条路线在结构化生成上的边界。**

### 1.3 交付物

| # | 交付物 | 形态 |
|---|---|---|
| D1 | 训练好的 3M 模型 checkpoint | `out/ckpt.pt` |
| D2 | 格律引擎（判定 + 约束生成） | `prosody/` + `decoding/` |
| D3 | 六组对照实验的结果与曲线 | `results/` + 图表 |
| D4 | 可现场演示的生成器 | CLI + 简单网页 |
| D5 | 报告（8–12 页）与答辩 PPT | `docs/` |

### 1.4 明确不做（范围外）

- 不训大模型，不做微调，不做 RAG
- 不做词（长短句）、不做古体诗、不做律诗对仗判定
- 不做 7×24 服务部署
- 不使用任何有版权的语料

## 3. 技术细节

### 3.1 模型

| 参数 | 值 | 说明 |
|---|---|---|
| 架构 | decoder-only Transformer | Pre-LN，weight tying |
| n_layer / n_head / n_embd | 6 / 4 / 192 | head_dim = 48 |
| block_size | 256 | 覆盖 5–6 首绝句 |
| vocab_size | ~5000 | 由语料决定，见 §3.2 |
| 参数量 | ~3.0M | 含 embedding |
| 位置编码 | 可学习绝对位置 | 够用，不必上 RoPE |
| 归一化 | LayerNorm（Pre-LN） | 比 Post-LN 稳 |
| dropout | 0.0 | 数据量足够时不需要 |

训练配置（`configs/small.yaml`）：

```yaml

batch_size: 32

```

### 3.2 数据

| 项 | 决定 |
|---|---|
| 语料 | 全唐诗为主（约 320 万字），宋词作可选扩展 |
| 来源 | [chinese-poetry](https://github.com/chinese-poetry/chinese-poetry) |
| 粒度 | **char-level**（约束按字施加，BPE 无法施加） |
| 繁简 | 统一转简体（`opencc`），**不能混用** |
| 稀有字 | 出现次数 `< 3` 的映射到 `<unk>` |
| 切分 | **按作品切分**，90/5/5，绝不按行 |
| 去重 | 完全重复 + 近似重复（去标点后比对） |

处理流程：

1. 读原始 JSON，按作品聚合成完整文本
2. 繁转简
3. 两级去重
4. 按作品随机切分（固定 seed）
5. 建词表，过滤稀有字
6. 编码为 `uint16` 写入 `.bin`

产出：

| 文件 | 内容 |
|---|---|
| `data/processed/train.bin` | uint16 token ids |
| `data/processed/val.bin` | uint16 token ids |
| `data/processed/meta.json` | `{"vocab_size": int, "itos": ["<unk>", "…"]}` |

数据加载用 `np.memmap` + 随机窗口，**不用 DataLoader**（规避 Windows `spawn` 问题）。

### 3.3 格律引擎

#### 3.3.1 四个基本句式（五言）

P = 平，Z = 仄。

| 句式 | 平仄 | 平起/仄起 | 句末 | 是否韵句 |
|---|---|---|---|---|
| A | `ZZPPZ` | 仄起 | 仄 | 否 |
| B | `PPZZP` | 平起 | 平 | 是 |
| C | `PPPZZ` | 平起 | 仄 | 否 |
| D | `ZZZPP` | 仄起 | 平 | 是 |

#### 3.3.2 格式由句式推导，不手工写死

规则两条：

- **对**：同一联上下句平仄相反（A↔B，C↔D）
- **粘**：上联下句与本联上句的第 2 字平仄相同

| 首句 | 推导 | 格式 | 平起/仄起 | 首句入韵 | rhyme_lines（0-indexed） |
|---|---|---|---|---|---|
| A | A→对→B→粘→C→对→D | `ABCD` | 仄起 | 否 | `(1, 3)` |
| B | B→对→D→粘→A→对→B | `BDAB` | 平起 | 是 | `(0, 1, 3)` |
| C | C→对→D→粘→A→对→B | `CDAB` | 平起 | 否 | `(1, 3)` |
| D | D→对→B→粘→C→对→D | `DBCD` | 仄起 | 是 | `(0, 1, 3)` |

**关键**："首句入不入韵"和"平起仄起"不是自由参数，都由首句句式唯一决定。真实选择空间只有 4 个。

推导结果**必须**用单元测试锁定（`tests/test_template.py`），规则理解错一个字符会导致全部实验作废。

#### 3.3.3 变体句式（默认关闭，W3 启用）

| 名称 | 基准句式 | 变体 | 说明 |
|---|---|---|---|
| 特拗 | C `PPPZZ` | `PPZPZ`（平平仄平仄） | 唐诗高频，**推荐启用** |
| 孤平救 | B `PPZZP` | `ZPPZP`（仄平平仄平） | 可选 |
| 对句救 | A `ZZPPZ` | `ZZZPZ` + 对句 `PPPZP` | 需跨句状态，**默认不做** |

**禁止**：`ZZPPP`（三平调），任何情况都不合法。

#### 3.3.4 平仄必须用中古音

普通话四声 ≠ 平仄。入声字（白、国、竹、石）在普通话读平/上/去声，但在中古音属仄。

**禁止使用 `pypinyin` 判平仄。** 必须查平水韵表（30 个平声韵部）。

#### 3.3.5 韵

- 平声韵，一韵到底
- 第一个韵脚字选定后，**韵部锁定**，后续韵脚只能取该韵部内的字
- 韵脚字平仄不可拗

### 3.4 约束解码

#### 3.4.1 核心流程

```
选首句句式 → 展开成模板 → 逐字 mask 解码 → 行级校验
```

逐字 mask 的含义：在每一步，把不在"当前允许集合"的 token logit 置 `-inf`，**只在合法集合上采样**。这样平仄和韵脚天然合法，不需要事后重试。

```python
def decode_line(model, state, temperature):
    for pos in range(5):
        allowed = allowed_chars(state, pos)          # set[str]
        logits = model.logits_at(ctx)                # (vocab,)
        masked = mask_logits(logits, allowed)        # 非法位置 -inf
        ch = sample(masked, temperature)
        state = advance(state, ch)
    return state.text
```

#### 3.4.2 格式必须前置决策

不能逐字决定格式。原因：第 1 句就锁定了平起/仄起和韵部，逐字决策必然在后半段无路可走。

#### 3.4.3 整句回退，不逐字回溯

逐字 backtracking 实现痛苦。改为**按句重试**：

```
生成第 i 句 → 校验 → 不合规则整句丢弃重来 → 最多 M 次（默认 20）
超过 M 次 → 记录失败，整首作废
```

#### 3.4.4 格式选择策略

| 策略 | 做法 | 成本 | 用途 |
|---|---|---|---|
| `fixed` | 调用方指定首句句式 | 1× | demo、调试 |
| `sample` | 按语料统计的格式频率加权采样 | 1× | 消融 |
| `search` | 4 句式 × K 韵部各生成，取最优似然 | 4K× | 主方法 |

`K` 取语料中前 10 个高频平声韵部，共 40 个组合，几秒内跑完。

### 3.5 评测

#### 3.5.1 自动指标

| 指标 | 定义 |
|---|---|
| 合律率 | `is_valid()` 通过的样本比例 |
| ppl（per-token） | 生成结果在模型下的困惑度 |
| **masked_prob** | 每步被 mask 掉的概率质量，**核心指标** |
| distinct-1 / distinct-2 | 生成多样性 |
| 单首耗时 | 端到端秒数 |
| 行重试次数 | 每行的失败重试分布 |

`masked_prob` 是整个项目信息量最大的指标：它直接量化"约束的价格"。

#### 3.5.2 人工评测

- 3 人盲评，每人 30 首（共 90 首，随机来自不同实验组）
- 5 分制：流畅度 / 意境 / 是否像人写的
- 计算组间一致性（Krippendorff's α 或简单百分比）

### 3.6 实验矩阵

| # | 方法 | 格式选择 | 变体 | 预期 |
|---|---|---|---|---|
| ① | 无约束 | — | — | 流畅但不合律（下界） |
| ② | Rejection sampling | 事后筛 | — | 合律率低、成本高 |
| ③ | 约束解码 | `fixed` | strict | 100% 合律，格式无多样性 |
| ④ | 约束解码 | `sample` | strict | 100% 合律，分布自然 |
| ⑤ | 约束解码 | `search` | strict | 质量高于 ④ |
| ⑥ | 约束解码 | `search` | strict + 特拗 | 最好（上界） |

③→④→⑤→⑥ 是"格式选择策略"的消融链，是本项目的创新点支撑。

另可加一组 `flex=True`（一三五不论）作为第 7 组，观察约束放松的效果。

## 4. 分工

依赖关系：

```
B(格律 API) ──┐
              ├──> C(解码 + 实验)
A(模型) ──────┘
```

**关键路径是 A**。但 C 依赖 B 的接口，所以 **B 必须在 W1 第 1 天交付 API stub**（函数签名 + `NotImplementedError`），否则 C 会空等一周。

```python
    strategy: str = "fixed",       # "fixed" | "sample" | "search"
    strict: bool = True,
    temperature: float = 0.8,
    max_line_retry: int = 20,
    seed: int | None = None,
) -> GenerationResult: ...
```

## 7. 注意事项

### 7.1 领域知识坑

| 坑 | 后果 | 做法 |
|---|---|---|
| 用拼音判平仄 | 入声字全错，合律率虚高 | 查平水韵表，禁用 `pypinyin` |
| 手工写死 4 个格式 | 某行错一个字符，全盘皆错 | 从 4 句式推导 + 单元测试 |
| 误把"首句入韵"当独立参数 | 组合数翻倍且自相矛盾 | 它由首句句式决定 |
| 把"一三五不论"写进模板字符 | 孤平/三平调漏判 | 模板存严格值，放宽在 `check_line` 做 |
| 以为拗救能让生成更容易 | 拒绝率暴涨 50 倍 | 逐字 mask 天然零重试，拗救只作对照 |

### 7.2 数据处理坑

| 坑 | 后果 | 做法 |
|---|---|---|
| 按行切分 train/val | 数据泄漏，val loss 虚低 | **按作品切分** |
| 繁简混用 | 词表翻倍，训练信号稀释 | 统一转简体 |
| 不去重 | 隐含泄漏 | 完全去重 + 近似去重 |
| 去掉标点 | 模型学不会断句 | 保留全角标点和 `\n` |
| 不过滤稀有字 | embedding 被长尾稀释 | `min_freq >= 3` |
| 数据进 git | 仓库膨胀 | `.gitignore` |

### 7.3 工程坑

| 坑 | 后果 | 做法 |
|---|---|---|
| Windows `num_workers > 0` | 无限递归 / 卡死 | 用 `memmap`，或加 `if __name__ == "__main__":` |
| 笔记本用电池跑 | 限频，时间翻倍 | 插电 + 性能模式 |
| 三个人同时跑训练 | OOM / 互相拖慢 | 共享排期表，一次只跑一个 |
| 初始 loss 不对 | 标签错位 / 数据全同 | 应约等于 `ln(vocab_size)` |
| 训练中途改代码 | 实验无法复现 | 跑长任务前先 commit |

### 7.4 止损方案（必须提前定好）

| 触发条件 | 降级动作 |
|---|---|
| W1 末平水韵表不可用 | 放弃格律判定，改用"句式结构 + 字数"弱约束，项目主张改为"结构约束" |
| W2 末无法生成合律五绝 | 降级为 rejection sampling（采样 1000 首筛 1 首），30 行代码保交付 |
| W3 中机器故障 | 用 Colab T4 跑，config 不变 |
| 训练不收敛 | 降到 4 层 / d=128 / ctx=128，数据减半 |

**每一次降级都要在报告里如实记录**，这本身是"失败分析"章节的素材。

### 7.5 协作坑

- **接口先行**：B 的 stub 必须在 W1 第 1 天就位，否则 C 空等。
- **不要跨目录改文件**：要改别人的代码就提 PR。
- **每个人都要能讲清别人的模块**，答辩必问基础概念（为什么除以 √d_k、什么是 TD 误差级别的细节）。
- **不要用 AI 生成代码后不理解**：理解不了的代码不要提交。
- **实验记录当场写**，不要事后凭记忆补。
